# Notelin

갤럭시 탭과 S펜을 우선으로 설계한, 서버와 로그인 없이 사용하는 필기 앱입니다. Android APK와 설치형 웹 앱(PWA)을 제공하며 기존 필기 엔진을 공유합니다.

배포 대상: **https://znh0o.github.io/mynotes/**

앱 이름은 **Notelin**입니다. 기존 노트와 설치 주소를 유지하기 위해 배포 경로 `/mynotes/`, IndexedDB 이름 `mynotes-v1`, 백업 내부 형식 `mynotes`는 유지합니다. 기존 MyNotes 백업 파일도 복원할 수 있습니다.

## 실행

Node.js 24 이상을 권장합니다. 의존성 버전은 `package-lock.json`으로 고정합니다.

```sh
npm ci
npm run dev
```

개발 주소: http://127.0.0.1:5173/mynotes/

```sh
npm test
npm run build
npm run preview
```

PWA와 오프라인 동작은 **production build + preview** 또는 HTTPS 배포 주소에서 검사하세요. 개발 서버에서는 Service Worker를 등록하지 않습니다.

```sh
# Windows: 설치된 Microsoft Edge로 검증
npm run test:e2e

# Linux/macOS/CI: Chromium을 설치하고 실행
npx playwright install --with-deps chromium
CI=1 npm run test:e2e

# 이미 배포된 사이트에서 동일한 흐름을 독립 브라우저 프로필로 검증
PLAYWRIGHT_BASE_URL=https://znh0o.github.io/mynotes/ npm run test:e2e
```

## Android APK

[최신 Android 설치 파일](https://github.com/znh0o/mynotes/releases/latest)에서 APK를 내려받아 설치합니다. Android 8 이상을 지원합니다. 웹 화면과 PDF 리소스를 APK에 포함하므로 설치 후 인터넷 없이 서재와 필기를 사용할 수 있습니다. 웹사이트 접속용 창이나 설치 안내 페이지는 APK에 표시하지 않습니다.

- PDF의 연결 프로그램에서 **Notelin → 항상**을 선택하면 기본 PDF 앱으로 사용할 수 있습니다. 다른 앱의 **공유 → Notelin**도 지원합니다. 가져온 PDF는 노트 사본으로 저장하며 원본 파일은 수정하지 않습니다.
- PDF 내보내기와 전체 백업은 Android의 **다른 이름으로 저장** 창에서 위치를 선택합니다.
- 태블릿은 시스템 바를 숨기고, 위에서 쓸어내리면 일시적으로 표시합니다. 휴대폰은 상태바를 유지합니다. 시스템 뒤로가기는 앱의 노트·서재·대화상자를 탐색합니다.
- 설정의 **업데이트 확인 → 다운로드 후 설치**로 앱 안에서 APK를 다운로드합니다. 체크섬·패키지 ID·버전·서명을 검증한 뒤 Android 설치 확인 창을 엽니다. 처음에는 이 앱에서의 설치 허용이 필요할 수 있습니다. 앱 ID와 서명키를 유지하며 업데이트합니다.
- PWA와 APK는 저장 공간이 다릅니다. **PWA 설정 → 전체 백업 → APK 설정 → 백업 파일 복원**으로 노트와 저장한 펜을 옮깁니다. 이전 형식 백업도 복원할 수 있습니다.

APK 빌드에는 Node 24, JDK 21, Android SDK 36이 필요합니다. `JAVA_HOME`, `ANDROID_HOME`을 설정하고 Windows에서 실행합니다.

```powershell
npm ci
npm run android:apk
```

결과는 `artifacts/Notelin-<버전>.apk`입니다. 서명키와 속성 파일은 저장소 밖 `%USERPROFILE%/.notelin/`에 생성하며 Git에 포함하지 않습니다. 다음 업데이트를 위해 이 두 파일을 함께 보관합니다. `npm run android:sync`로 Android 프로젝트를 갱신할 수 있습니다. 릴리스 업로드는 검증 완료 후 `node scripts/publish-android.mjs`로 진행하며 APK와 SHA-256 파일을 함께 게시합니다. GitHub Actions는 웹 테스트와 Android 빌드·Lint를 검사합니다.

## 설치 및 사용

1. 갤럭시 탭의 최신 Chrome 또는 Samsung Internet에서 배포 주소에 접속합니다.
2. “오프라인 사용 준비가 완료됐어요” 안내까지 기다립니다. 최초 설치에는 네트워크가 필요합니다. 앱과 PDF 리소스의 사전 캐시 용량은 약 6MB입니다.
3. 설치 페이지의 **Notelin 설치하기**를 누르거나 브라우저 메뉴의 **앱 설치 / 홈 화면에 추가**를 선택합니다.
4. 설치된 앱을 실행하고 새 노트를 만듭니다. 기본 설정에서는 **S펜으로 필기, 손가락으로 이동**합니다. 마우스 필기도 지원합니다.
5. 두 손가락으로 확대·이동합니다. “손가락 필기”를 켜면 손가락으로도 쓸 수 있습니다.
6. 설정 → **전체 백업**으로 주기적으로 백업 파일을 다른 곳에 보관하세요. 브라우저 사이트 데이터 삭제는 설치된 PWA의 데이터에도 영향을 줍니다.

일반 브라우저에는 설치 페이지만 표시하며, 여기서 밝게·어둡게·기기 설정을 선택할 수 있습니다. 설치된 갤럭시 탭 앱은 매니페스트의 전체 화면 모드로 실행하고, 휴대폰 앱은 상태 표시줄을 유지하는 standalone 모드로 실행합니다. 전체 화면 전환 버튼은 에디터에서 제거했습니다. 운영체제가 시스템 표시줄을 일시적으로 보여주는 동작은 기기와 브라우저가 제어합니다. 기존 Samsung Internet 설치 앱의 매니페스트 변경은 WebAPK 갱신 시점에 반영되며, 서비스 워커 업데이트와 시점이 다를 수 있습니다. 화면 모드는 앱 인증 수단으로 사용하지 않습니다.

펜 굵기는 도구 모음의 **색상 바로 옆 슬라이더** 또는 **− / +**로 조절합니다. 분할 화면과 모바일에서도 표시되며, S펜·손가락·마우스 드래그와 키보드를 지원합니다. 범위는 0.5–20, 단계는 0.5이며 새로 쓰는 획에 적용됩니다.

도구 모음의 **펜** 버튼을 누르면 볼펜·만년필·연필이 한 목록에 열립니다. **초록 볼펜·노란 만년필·빨간 연필**처럼 종류·색상·굵기·연필 진하기를 조합한 펜을 최대 12개까지 저장하고 순서와 이름을 바꿀 수 있습니다. 저장한 펜 구성은 모든 노트에서 공유됩니다. 형광펜은 별도 도구이며 노트별로 굵기와 색상을 기억합니다.

색상 5개는 도구 모음의 팔레트에서 바로 고르고, **기본 색상 편집** 또는 **색상 선택**을 누르면 도구 옆 팝업에서 색을 조절할 수 있습니다. 색상 5개도 노트마다 저장됩니다. 파란 문서 막대의 **보기 옵션**에서 두 페이지 보기를 켜면 맞닿은 두 페이지를 함께 보고, 다른 쪽 페이지에도 바로 필기할 수 있습니다.

서재와 폴더 안의 노트 목록은 검색·정렬 옆 **한 줄** 메뉴에서 **4개·5개·6개**로 배치할 수 있습니다. 선택은 이 기기에 저장되어 노트를 열었다 돌아오거나 앱을 다시 실행해도 유지됩니다. **자동**은 화면 너비에 맞춰 기존 배치로 돌아갑니다.

휴지통에서는 **PDF 가져오기·새 노트** 버튼을 숨깁니다. 삭제한 노트의 메뉴에서 복구하거나 영구 삭제할 수 있습니다.

태블릿 도구 모음은 한 줄이고, 휴대폰에서는 화면 아래쪽에 두 줄로 배치합니다. **지우개**를 누르면 **스트로크 지우개**(닿은 획 전체)와 **펜 지우개**(문지른 부분)를 바로 고를 수 있습니다. 크기와 종류는 이 기기에 저장됩니다. S펜 측면 버튼을 누른 채 종이를 문지르면 선택한 방식으로 지우고, 버튼을 놓으면 원래 도구로 돌아옵니다. 필기 도중 누르거나 놓는 동작과 버튼을 누른 채 펜을 떼었다 다시 대는 동작도 처리하며, 공중에서는 지우지 않습니다. 브라우저가 펜 버튼 이벤트를 전달해야 사용할 수 있습니다.

지우개 범위는 종이 위의 **원**으로 표시합니다. 펜 호버·마우스 이동·지우는 동작을 따라가며, 종이 확대 배율을 반영합니다. 크기를 조절하면 현재 보이는 종이 중앙에도 잠깐 원을 미리 표시합니다. 이 원은 필기 데이터, 썸네일이나 PDF에 포함되지 않습니다.

**갤럭시 탭 S10+ / 삼성인터넷 30**에서 확인한 로그에는 버튼 입력이 표준 지우개 신호 대신 압력 0의 일반 클릭으로 나타났습니다. 이를 펜촉 접촉으로 오인하여 허공에서도 필기하던 오류를 수정했습니다. 압력 0인 입력만으로 쓰거나 지우지 않습니다. 이 환경을 위한 **삼성인터넷 버튼 호환**은 삼성인터넷에서 기본으로 켜지며, 지우개 선택창에서 끄거나 다시 켤 수 있습니다. 종이 가까이에서 **펜을 띄운 채 버튼을 한 번 눌렀다 놓으면 펜 ↔ 지우개로 전환**하고, 전환 후 **버튼을 놓고 문지릅니다**. 이전에 쓰던 볼펜·만년필·연필·형광펜을 기억합니다. 버튼을 누른 채 지우는 방식과는 다르며, 실제 기기에서는 전환 여부를 확인해야 합니다. 표준 측면 버튼 신호를 전달하는 환경에서는 기존의 누른 채 지우기도 유지합니다.

버튼을 누를 때 **에어 커맨드**가 열리면 기기의 **설정 → 유용한 기능 → S펜 → 에어 커맨드 → 펜 버튼으로 에어 커맨드 열기**를 끄세요. 그런 다음 버튼을 누른 채 펜촉을 종이에 대고 문지릅니다. PWA에서 시스템 에어 커맨드 설정을 바꾸거나 시스템이 소비한 버튼 입력을 강제로 받을 수는 없습니다. 설정을 꺼도 기기·브라우저가 버튼 입력을 전달하지 않으면 화면 지우개를 사용해야 합니다. 지우개 선택창에도 같은 안내를 제공합니다. 설정 경로는 [삼성 공식 안내](https://www.samsung.com/us/support/troubleshoot/TSG10002409/)를 참고했습니다.

설정을 꺼도 안 되면 지우개 선택창의 **S펜 버튼 입력 확인**에서 평소 필기와 버튼을 누른 필기를 차례로 테스트하세요. 펜 감지·표준 버튼·호환 전환 입력을 구분해 보여주며 **진단 결과 복사**로 브라우저 정보와 버튼·압력 값을 복사할 수 있습니다. 이 테스트는 실제 노트에 그리지 않습니다. 펜이 화면에서 멀리 떨어진 상태의 Bluetooth 에어 액션은 구현하지 않았으며, 현재 동작은 화면 가까이에서 브라우저가 전달하는 펜 입력을 사용합니다.

오른쪽 **필기 옵션** 버튼에서 손가락 필기, 속지 설정과 도형 종류를 설정합니다. 옵션은 필기 화면 위에 잠시 열리므로 작업 영역의 높이를 줄이지 않습니다. 좁은 화면에서는 왼쪽 도구 목록을 가로로 밀어 사용하고 색상·굵기는 고정 표시합니다.

**볼펜**은 힘을 줘도 설정한 굵기를 유지합니다. **만년필**은 필압과 고정된 펜촉에 대한 획 방향으로 굵기가 달라지고 양 끝이 가늘어집니다. **연필**은 종이 결을 따라 이어진 흑연 무늬와 연속된 밑색으로 표현합니다. 흰 점을 무작위로 뚫지 않으면서 옅고 진한 결이 보이도록 했으며, 화면과 PDF가 같은 질감을 사용합니다. 굵기 자리의 선택 메뉴를 **진하기**로 바꾸면 10–100% 슬라이더와 − / +로 조절합니다. 새 획의 굵기와 진하기는 필압과 관계없이 고정되며, 진하기 선택은 다시 실행해도 유지합니다. 연필 질감은 획에 저장한 시드로 재현하므로 다시 열거나 백업을 복원해도 바뀌지 않습니다. 기존 볼펜·만년필 획은 저장 당시 표현을 유지하고, 새로 쓰는 획부터 새 펜촉을 적용합니다.

**타이핑**은 텍스트 도구를 누르면 페이지 여백 안의 **본문**에서 바로 시작합니다. 글상자 테두리 없이 문서처럼 줄바꿈하며, 페이지가 차면 새 페이지를 만들어 이어 씁니다. 손글씨·이미지의 위치는 본문 줄 배치에 반영하지 않고 원본 위치와 획을 보존합니다. 타이핑 모드의 펜 터치는 새 필기 획을 만들지 않습니다. 본문은 올가미 이동 대상에서 제외됩니다. 한글 조합 입력과 자동 저장을 지원하며, 페이지 분할 시 본문·새 페이지·노트의 페이지 순서를 함께 저장합니다.

타이핑 도구를 선택하면 상단의 기존 굵기 막대와 − / +가 **글자 크기(10–100)** 조절로 바뀝니다. 펜으로 돌아가면 원래 펜 굵기를 복원합니다. 아래 서식 도구에도 **글자 크기 − / 숫자 / +**가 있습니다. 숫자를 누르면 전체 선택되어 바로 새 크기로 바꿀 수 있고, 입력 중인 본문/글상자와 이후 타이핑에 즉시 반영합니다. 숫자 입력을 마치기 전에 크기 버튼을 눌러도 이전 값으로 되돌아가지 않습니다. 새로 연 본문은 처음부터 표시하고, 같은 편집 화면 안에서는 직전 커서 위치를 유지합니다. 입력란의 높이와 커서 위치는 별도 DOM에서 측정하여 Android 키보드가 열릴 때 활성 입력란을 접었다 펴지 않습니다.

새 버전이 다운로드되면 서재의 **오늘의 생각을 펼쳐보세요** 배너가 업데이트 안내와 **지금 업데이트** 버튼으로 바뀝니다. 버튼을 누르면 필기를 저장하고 새 버전을 적용하며, 최신 상태에서는 원래 배너를 보여줍니다. 설정의 업데이트 확인·적용도 계속 사용할 수 있습니다.

서식 도구에서 크기·굵게·기울임·정렬을 바꾸고 기존 팔레트로 글자색을 조절합니다. 별도 글상자가 필요하면 서식 도구의 **본문 → 글상자**로 전환한 뒤 종이를 누릅니다. 이전에 저장한 글상자도 이 모드에서 다시 편집할 수 있고, 위 손잡이로 이동하거나 오른쪽 손잡이로 너비를 조절합니다. **입력 완료** 또는 다른 도구/페이지/서재로 이동하면 편집을 마칩니다. **입력 취소/Esc**는 이번 페이지에서 시작한 편집을 되돌리고, Ctrl+Enter는 완료합니다.

**직선 정리**는 선을 그린 뒤 펜을 떼지 않고 끝에서 약 0.6초 멈추면 작동합니다. 정리된 상태에서 펜을 움직여 끝점을 바꾸고 떼면 확정됩니다. 점이나 닫힌 필기에는 적용하지 않으며, 필기 옵션의 **길게 멈추면 직선으로**에서 끌 수 있습니다. 홈·설정 등 앱 UI의 브라우저 확대는 막고, 종이의 두 손가락·Ctrl+휠 확대는 유지합니다.

## 필기와 데이터 구조

프레임워크 없이 TypeScript와 Vite를 사용했습니다. 필기 중 UI 렌더링을 피하고 DOM 인터페이스와 입력·Canvas 처리를 분리하기 위한 선택입니다.

```text
src/
  main.ts                   앱 전환, PWA 설치·업데이트, 설정
  data/model.ts             노트·페이지·획·오브젝트 타입
  data/store.ts             IndexedDB, 직렬 저장 큐, 백업·복원
  data/pdf.ts               PDF.js, 이미지 로딩, 썸네일, PDF 내보내기
  engine/InkEngine.ts        Pointer Events, 입력 상태, 이력, 선택
  engine/geometry.ts         올가미·이동·확대·획 분할 지우기
  engine/render.ts           필압 곡선, 도형·텍스트·이미지, 속지
  engine/brush.ts            만년필 펜촉·연필 입자, 화면/PDF 공통 벡터
  ui/library.ts             서재·폴더·노트 관리
  ui/editor.ts              편집 도구, 페이지, 확대·이동
  ui/common.ts              접근성 레이블, 모달, 메뉴, 알림
  ui/history.ts             앱 내부 뒤로가기·대화상자 이력
  ui/transitions.ts         이전 화면 슬라이드·모션 줄이기 지원
  ui/page-previews.ts       보이는 페이지 미리보기 생성·저장
  style.css                 반응형 태블릿·모바일 인터페이스
  theme.css                 선명한 블루 포인트·텍스트 대비
scripts/prepare-assets.mjs   아이콘 생성, 오프라인 PDF 리소스 복사
tests/                      저장·기하 단위 테스트 및 실제 브라우저 테스트
```

- 좌표는 화면 픽셀이 아닌 **페이지 좌표**입니다. 펜 입력은 `getBoundingClientRect()`에서 페이지 좌표로 변환하며, DPR·확대·회전 레이아웃 변경 후에도 저장된 좌표를 유지합니다.
- 각 획에 좌표·필압·시간·색·도구·굵기를 저장합니다. 이미지만 저장하지 않습니다.
- 배경, 확정 필기, 진행 중 필기를 Canvas 레이어 3개로 분리합니다. PDF 배경은 필기 때 다시 렌더링하지 않습니다.
- `getCoalescedEvents()`가 있으면 사용하고, 없으면 기본 이벤트로 대체합니다. 중간 점을 보간해 곡선을 만들고, 필압 외곽선을 한 번 채워 획의 진하기를 일정하게 유지합니다.
- 볼펜·연필·형광펜은 확정된 곡선을 작은 구간으로 캐시하고 펜 끝 주변만 `requestAnimationFrame`으로 갱신합니다. 획이 길어져도 흑연 입자를 매번 다시 생성하지 않습니다. 펜을 뗄 때는 진행 중 레이어를 합성하며 페이지 전체를 재생하지 않습니다.
- 연필은 재사용하는 저대비 질감 패턴과 연속된 바탕으로 흰 점과 거친 입자를 줄입니다. 새 획에 고정 진하기를 저장하고 필압에 따른 굵기·진하기 변화를 적용하지 않습니다. 이전 획의 필압 정보는 보존합니다. PDF에도 같은 재료를 벡터 타일 패턴으로 포함합니다.
- 완료된 필기는 변경하지 않고, 올가미로 바꿀 오브젝트만 복사합니다. 실행 취소와 자동 저장 때문에 모든 기존 좌표를 매번 깊은 복사하지 않습니다.
- 앱의 모든 버튼은 문서에 공통으로 연결한 S펜·터치 탭 처리로 실행합니다. 서재·툴바·설정·메뉴뿐 아니라 대화상자의 확인·취소·폼 제출도 짧은 탭을 지원하고, 늦게 도착한 클릭은 억제해 중복 실행을 막습니다. 마우스·키보드는 기본 동작을 유지하고 스와이프는 탭으로 바꾸지 않습니다. 설정 창은 저장 공간 조회를 기다리지 않고 열립니다.
- 펜을 감지하면 800ms 동안 터치를 필터링합니다. S펜 뒤집기/지우개 버튼 이벤트를 브라우저가 노출하면 지우개로 처리합니다.
- 현재 페이지의 필기만 로딩하고 썸네일은 저장합니다. PDF 문서는 최대 2개, 이미지 캐시는 활성 페이지를 보존하면서 제한합니다. Canvas 해상도 상한을 둡니다.
- 저장 큐는 호출 시점의 스냅샷을 만들고 트랜잭션을 순차 처리합니다. 늦은 이전 저장이 새 편집을 덮어쓰지 않습니다. 실패 후에도 화면의 편집 데이터는 유지하고 “지금 저장”으로 재시도할 수 있습니다. 실패 시 노트 전환을 완료하지 않습니다.
- 백업은 PDF·이미지 원본까지 포함합니다. 복원은 검증 후 한 트랜잭션으로 새 ID를 생성하여 추가하고 기존 노트를 보존합니다.
- PDF 원본은 Blob, 필기는 페이지별 오브젝트로 분리합니다. 펜·만년필·형광펜·도형과 속지는 PDF 벡터 경로로 내보내고, 원본 PDF 페이지도 벡터로 유지합니다. 회전·크롭된 페이지는 벡터 Form XObject로 정규화합니다. PNG/JPEG는 원본 해상도로 포함합니다.
- PDF.js와 워커는 모두 공식 `legacy` 호환성 빌드를 사용합니다. `Map.getOrInsertComputed` 등 최신 API가 없는 브라우저에서도 필요한 호환 처리가 로드됩니다.
- 핀치·휠 확대 중에는 한 프레임에 한 번 기존 Canvas를 확대하고, 제스처가 끝날 때 필기와 PDF를 선명하게 다시 그립니다. 제스처 도중 Canvas 픽셀 버퍼를 반복 생성하지 않습니다.
- PDF를 가져오면 옆 목록에 실제 페이지 미리보기가 자동으로 나타납니다. 화면 근처 페이지부터 하나씩 생성하고 필기·확대 중에는 새 작업을 미룹니다. 미리보기는 페이지 변경 번호를 확인한 뒤 저장하므로 최신 편집을 덮어쓰지 않습니다.
- 기기·브라우저 뒤로가기는 열린 설정·대화상자·메뉴·모바일 탐색 목록을 먼저 닫고, 그다음 이전 서재 화면으로 이동합니다. 노트 탭을 바꾼 뒤에도 서재로 돌아올 수 있고 서재 첫 화면에서는 앱 안에 머무릅니다. 필기에서 홈으로 돌아갈 때 이전 화면을 슬라이드하며, 시스템의 모션 줄이기 설정을 따릅니다. OS의 강제 종료·앱 전환은 제어하지 않습니다.
- 더 선명한 블루 포인트, 활성 도구와 탐색 버튼, 읽기 쉬운 글자 대비를 적용했습니다. 저장된 종이·필기 색은 그대로 유지합니다.
- 설정의 **업데이트 확인**은 항상 표시됩니다. 새 Service Worker를 다운로드한 후 **저장 후 새 버전 적용**을 누르면 필기를 먼저 저장하고 업데이트합니다. 최신·오프라인·다운로드 실패 상태를 표시하며 사이트 데이터는 삭제하지 않습니다.
- 필기 화면에서는 아래로 당겨 새로고침하는 동작과 F5·Ctrl/Cmd+R을 막습니다. 브라우저 자체의 새로고침·닫기에는 지원되는 환경에서 확인창을 표시합니다. 앱의 명시적인 업데이트는 저장 후 새로고침을 허용합니다. 모바일 OS 강제 종료나 브라우저 UI를 웹에서 완전히 차단할 수는 없습니다.

## 검증

`npm test`는 빠르게 교차하는 지우개, 부분 지우개 필압 유지, 올가미, 대형 획 경계, 저장 스냅샷 순서, 실패 트랜잭션 롤백·재시도, 첫 페이지 미리보기 갱신을 검사합니다.

`npm run test:e2e`는 production build를 실제 Chromium 계열 브라우저에서 실행합니다. 노트 생성, DevTools 프로토콜의 **펜 입력·압력**, 필기 저장, 실행 취소·다시 실행, 새로고침 복원, 텍스트·페이지 추가, 휴지통 복구, 모바일 폴더 관리, 오프라인 재실행, **오프라인에서 PDF 가져오기·주석·내보내기·전체 백업·복원**을 검증합니다.

추가 회귀 검사에는 최신 Map API를 제거한 창·PDF 워커에서의 PDF 열기, 손상된 PDF 표시 실패 후 홈 복귀와 필기 보존, 실제 Service Worker 버전 교체 후 노트 보존, 첫 S펜·터치 탭의 도구 전환, 핀치/휠 제스처 도중 Canvas 버퍼 재생성 0회, 새로고침 단축키 차단 및 브라우저 확인창이 포함됩니다. 벡터 내보내기 검사는 출력 PDF에 불필요한 전체 페이지 비트맵이 없고 회전된 원본도 벡터 Form으로 남는지 검사합니다.

탐색 검사는 설정·폴더·즐겨찾기·최근·휴지통·모바일 탐색 목록·메뉴에서 실제 History 뒤로가기를 실행하고, 홈에서 반복해도 같은 문서에 머무르는지 확인합니다. 필기 후 슬라이드 복귀와 저장 보존, 탭 전환 후 뒤로가기, 서로 다른 PDF 페이지 미리보기 생성과 재실행 후 캐시도 검사합니다.

브러시 검사는 펜을 떼기 전 Canvas에서 볼펜·형광펜·직선·얇은 연필의 모든 단면이 이어지는지 확인합니다. 올가미 선택 후에도 필기에 점선 상태가 남지 않는지, 연필 곡선의 연속성·고정 진하기의 필압 독립성·진하기 수치 변경·재실행과 백업 복원 후 질감도 검사합니다.

실제 갤럭시 탭 하드웨어 테스트는 별도로 필요합니다. PC 자동화가 S펜의 실제 지연이나 손바닥 크기 입력을 재현하지는 못합니다.

## 현재 제한과 다음 단계

요청한 Phase 1을 기반으로 Phase 2–4의 주요 도구를 연결한 첫 버전입니다. 전체 요구사항이 모두 완료된 최종 네이티브 노트 앱 수준으로 간주하면 안 됩니다.

- **완전한 연속 다중 페이지 스크롤은 미구현**입니다. 현재는 한 페이지를 스크롤하며 버튼·썸네일·페이지 번호로 전환하고, 마우스 휠로 아래 경계에서 다음 페이지로 이어갈 수 있습니다.
- 실행 취소 이력은 현재 페이지의 오브젝트 편집 40단계이며, 페이지 전환 후 초기화됩니다. 페이지 삭제·속지 변경은 이 이력으로 되돌릴 수 없습니다. 노트 삭제는 휴지통에서 복구됩니다.
- 예측 입력(`getPredictedEvents`)은 미사용입니다. 실제 S펜 튜닝과 긴 필기 성능 측정이 다음 단계입니다.
- 웹 팜 리젝션은 하드웨어·OS·브라우저 영향을 받습니다. 네이티브 수준을 보장하지 않습니다. S펜 에어 액션과 측면 버튼의 브라우저 미노출 동작은 제어하지 못합니다.
- 기본 본문은 페이지 여백에 맞춰 입력하며, 별도 글상자는 직접 재편집하고 손잡이로 이동·너비를 조절합니다. 서식은 본문 페이지 또는 글상자 단위이며 부분별 서식은 미지원입니다. 별도 글상자·이미지는 올가미로 이동·복사·확대·삭제할 수 있으며, 이미지 자르기·회전은 미구현입니다. 앞 페이지를 수정하면 넘친 글을 위한 새 페이지가 삽입되며, 기존 다음 페이지의 본문을 당겨 채우는 전체 문서 재배치는 미구현입니다.
- 노트 내 검색은 **입력 텍스트**만 지원합니다. 손글씨 OCR, PDF 본문 검색, 모든 검색 결과 목록은 미구현입니다.
- 펜·형광펜·도형은 PDF에서도 벡터로 유지됩니다. 직접 입력한 한글 등 유니코드 텍스트는 브라우저 글꼴 모양을 보존하기 위해 글상자만 4배 해상도 이미지로 포함합니다. 원본 이미지·스캔 PDF 자체의 해상도를 높이지는 못합니다. Notelin에서 획별 재편집하려면 원본 백업도 보관하세요.
- 암호화·권한 제한 PDF, 양식 편집, PDF 자체 링크·주석 상호작용은 지원 범위 밖입니다. PDF 150MB, 이미지 20MB/4천만 화소, 백업 복원 400MB 제한이 있습니다. 대형 파일은 기기 RAM의 제약을 받습니다.
- 기기 간 클라우드 동기화·로그인·협업·자동 클라우드 백업은 없습니다. 동일 브라우저 프로필 내 저장만 지원합니다. 다중 창에서 동일 노트를 동시에 편집하는 협업 충돌 해결은 미구현입니다.
- 자동 저장은 완료된 획/편집 직후 시작합니다. 브라우저 강제 종료가 저장 완료 전에 발생하면 마지막 진행 중 획은 유실될 수 있습니다. 영구 저장은 브라우저의 허가에 따릅니다.
- 재실행 시 서재를 엽니다. 저장한 페이지와 필기는 보존되지만 마지막 탭·선택 도구·확대율 복원은 미구현입니다.

## GitHub Pages 배포

`.github/workflows/deploy.yml`은 `main` push마다 단위 테스트 → 빌드 → Chromium 브라우저 테스트 → Pages 배포를 실행합니다. PR에서는 테스트만 실행합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 설정합니다.
2. `main`에 push하거나 Actions → **Test and deploy Notelin PWA → Run workflow**를 실행합니다.
3. Actions의 `deploy` 성공 후 https://znh0o.github.io/mynotes/ 에서 확인합니다.

```sh
git remote add origin https://github.com/znh0o/mynotes.git
git push -u origin main
```

`base`, manifest `start_url`·`scope`, Service Worker fallback은 모두 `/mynotes/`입니다. 저장소 이름을 바꾸면 `vite.config.ts`와 테스트의 경로도 함께 바꾸세요. GitHub Pages에는 서버나 별도 환경변수가 필요 없습니다.

## 갤럭시 탭 실기기 확인 절차

1. PWA 설치 후 가로·세로·분할 화면에서 서재와 툴바를 확인합니다.
2. S펜으로 느린 곡선·빠른 글씨·점·가벼운/강한 압력 획을 작성합니다.
3. 펜이 닿는 동안 손바닥을 올려 추가 획이 생기는지 확인합니다. 손가락 필기를 꺼서 시작합니다.
4. 두 손가락으로 50%/200% 확대 후 같은 PDF의 글자 위치에 선을 긋고 정합성을 확인합니다.
5. 앱을 닫았다 다시 열어 필기를 확인하고, 비행기 모드에서 앱을 재시작합니다.
6. 비행기 모드에서 저장한 PDF를 가져오고 필기 후 내보낸 파일을 PDF 뷰어에서 비교합니다.
7. 백업을 다운로드하고 복원하여 기존 노트와 “(복원)” 사본이 모두 남는지 확인합니다.
8. 브라우저 개발자 도구의 저장소 제한 또는 테스트 환경에서 저장 실패를 유발하고 실패 안내·재시도를 확인합니다. 실제 중요한 데이터를 지우며 테스트하지 마세요.
