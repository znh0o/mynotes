# MyNotes

갤럭시 탭과 S펜을 우선으로 설계한, 서버와 로그인 없이 사용하는 필기 **PWA**입니다. Goodnotes에서 영감을 받은 독자적인 서재와 넓은 필기 화면을 제공합니다.

배포 대상: **https://znh0o.github.io/mynotes/**

실제 저장소가 `znh0o/mynotes`이므로 모든 경로는 소문자 `/mynotes/`로 통일했습니다. `/MyNotes/`와는 다른 경로입니다.

## 실행

Node.js 24 이상을 권장합니다. 의존성 버전은 `package-lock.json`으로 고정합니다.

```sh
npm ci
npm run dev
```

개발 주소: http://127.0.0.1:5173/mynotes/

```sh
npm test
npm run build
npm run preview
```

PWA와 오프라인 동작은 **production build + preview** 또는 HTTPS 배포 주소에서 검사하세요. 개발 서버에서는 Service Worker를 등록하지 않습니다.

```sh
# Windows: 설치된 Microsoft Edge로 검증
npm run test:e2e

# Linux/macOS/CI: Chromium을 설치하고 실행
npx playwright install --with-deps chromium
CI=1 npm run test:e2e

# 이미 배포된 사이트에서 동일한 흐름을 독립 브라우저 프로필로 검증
PLAYWRIGHT_BASE_URL=https://znh0o.github.io/mynotes/ npm run test:e2e
```

## 설치 및 사용

1. 갤럭시 탭의 최신 Chrome 또는 Samsung Internet에서 배포 주소에 접속합니다.
2. “오프라인 사용 준비가 완료됐어요” 안내까지 기다립니다. 최초 설치에는 네트워크가 필요합니다. 앱과 PDF 리소스의 사전 캐시 용량은 약 6MB입니다.
3. 브라우저 메뉴의 **앱 설치 / 홈 화면에 추가**를 선택합니다. 설치 이벤트를 지원하는 브라우저에서는 설정의 **MyNotes 설치**도 사용할 수 있습니다.
4. 설치된 앱을 실행하고 새 노트를 만듭니다. 기본 설정에서는 **S펜으로 필기, 손가락으로 이동**합니다. 마우스 필기도 지원합니다.
5. 두 손가락으로 확대·이동합니다. “손가락 필기”를 켜면 손가락으로도 쓸 수 있습니다.
6. 설정 → **전체 백업**으로 주기적으로 백업 파일을 다른 곳에 보관하세요. 브라우저 사이트 데이터 삭제는 설치된 PWA의 데이터에도 영향을 줍니다.

펜 굵기는 도구 모음의 **색상 바로 옆 슬라이더** 또는 **− / +**로 조절합니다. 분할 화면과 모바일에서도 표시되며, S펜·손가락·마우스 드래그와 키보드를 지원합니다. 범위는 0.5–20, 단계는 0.5이며 새로 쓰는 획에 적용됩니다.

도구 모음은 한 줄입니다. 오른쪽 **필기 옵션** 버튼에서 손가락 필기, 속지 설정, 지우개 모드·도형 종류를 설정합니다. 옵션은 필기 화면 위에 잠시 열리므로 작업 영역의 높이를 줄이지 않습니다. 좁은 화면에서는 왼쪽 도구 목록을 가로로 밀어 사용하고 색상·굵기는 고정 표시합니다.

**볼펜**은 힘을 줘도 설정한 굵기를 유지합니다. **만년필**은 필압과 고정된 펜촉에 대한 획 방향으로 굵기가 달라지고 양 끝이 가늘어집니다. **연필**은 종이 위의 흑연 입자처럼 표현하며, 필압은 주로 진하기에 반영합니다. 연필 질감은 획에 저장한 시드로 재현하므로 다시 열거나 백업을 복원해도 바뀌지 않습니다. 기존 버전의 획은 저장 당시 표현을 유지하고, 새로 쓰는 획부터 새 브러시를 적용합니다.

## 필기와 데이터 구조

프레임워크 없이 TypeScript와 Vite를 사용했습니다. 필기 중 UI 렌더링을 피하고 DOM 인터페이스와 입력·Canvas 처리를 분리하기 위한 선택입니다.

```text
src/
  main.ts                   앱 전환, PWA 설치·업데이트, 설정
  data/model.ts             노트·페이지·획·오브젝트 타입
  data/store.ts             IndexedDB, 직렬 저장 큐, 백업·복원
  data/pdf.ts               PDF.js, 이미지 로딩, 썸네일, PDF 내보내기
  engine/InkEngine.ts        Pointer Events, 입력 상태, 이력, 선택
  engine/geometry.ts         올가미·이동·확대·획 분할 지우기
  engine/render.ts           필압 곡선, 도형·텍스트·이미지, 속지
  engine/brush.ts            만년필 펜촉·연필 입자, 화면/PDF 공통 벡터
  ui/library.ts             서재·폴더·노트 관리
  ui/editor.ts              편집 도구, 페이지, 확대·이동
  ui/common.ts              접근성 레이블, 모달, 메뉴, 알림
  ui/history.ts             앱 내부 뒤로가기·대화상자 이력
  ui/transitions.ts         이전 화면 슬라이드·모션 줄이기 지원
  ui/page-previews.ts       보이는 페이지 미리보기 생성·저장
  style.css                 반응형 태블릿·모바일 인터페이스
  theme.css                 선명한 블루 포인트·텍스트 대비
scripts/prepare-assets.mjs   아이콘 생성, 오프라인 PDF 리소스 복사
tests/                      저장·기하 단위 테스트 및 실제 브라우저 테스트
```

- 좌표는 화면 픽셀이 아닌 **페이지 좌표**입니다. 펜 입력은 `getBoundingClientRect()`에서 페이지 좌표로 변환하며, DPR·확대·회전 레이아웃 변경 후에도 저장된 좌표를 유지합니다.
- 각 획에 좌표·필압·시간·색·도구·굵기를 저장합니다. 이미지만 저장하지 않습니다.
- 배경, 확정 필기, 진행 중 필기를 Canvas 레이어 3개로 분리합니다. PDF 배경은 필기 때 다시 렌더링하지 않습니다.
- `getCoalescedEvents()`가 있으면 사용하고, 없으면 기본 이벤트로 대체합니다. 중간 점을 보간해 곡선을 만들고, 필압 외곽선을 한 번 채워 획의 진하기를 일정하게 유지합니다.
- 진행 중 필기는 `requestAnimationFrame`으로 그립니다. 필기 중 UI 전체를 갱신하지 않습니다.
- 펜을 감지하면 800ms 동안 터치를 필터링합니다. S펜 뒤집기/지우개 버튼 이벤트를 브라우저가 노출하면 지우개로 처리합니다.
- 현재 페이지의 필기만 로딩하고 썸네일은 저장합니다. PDF 문서는 최대 2개, 이미지 캐시는 활성 페이지를 보존하면서 제한합니다. Canvas 해상도 상한을 둡니다.
- 저장 큐는 호출 시점의 스냅샷을 만들고 트랜잭션을 순차 처리합니다. 늦은 이전 저장이 새 편집을 덮어쓰지 않습니다. 실패 후에도 화면의 편집 데이터는 유지하고 “지금 저장”으로 재시도할 수 있습니다. 실패 시 노트 전환을 완료하지 않습니다.
- 백업은 PDF·이미지 원본까지 포함합니다. 복원은 검증 후 한 트랜잭션으로 새 ID를 생성하여 추가하고 기존 노트를 보존합니다.
- PDF 원본은 Blob, 필기는 페이지별 오브젝트로 분리합니다. 펜·만년필·형광펜·도형과 속지는 PDF 벡터 경로로 내보내고, 원본 PDF 페이지도 벡터로 유지합니다. 회전·크롭된 페이지는 벡터 Form XObject로 정규화합니다. PNG/JPEG는 원본 해상도로 포함합니다.
- PDF.js와 워커는 모두 공식 `legacy` 호환성 빌드를 사용합니다. `Map.getOrInsertComputed` 등 최신 API가 없는 브라우저에서도 필요한 호환 처리가 로드됩니다.
- 핀치·휠 확대 중에는 한 프레임에 한 번 기존 Canvas를 확대하고, 제스처가 끝날 때 필기와 PDF를 선명하게 다시 그립니다. 제스처 도중 Canvas 픽셀 버퍼를 반복 생성하지 않습니다.
- PDF를 가져오면 옆 목록에 실제 페이지 미리보기가 자동으로 나타납니다. 화면 근처 페이지부터 하나씩 생성하고 필기·확대 중에는 새 작업을 미룹니다. 미리보기는 페이지 변경 번호를 확인한 뒤 저장하므로 최신 편집을 덮어쓰지 않습니다.
- 기기·브라우저 뒤로가기는 열린 설정·대화상자·메뉴·모바일 탐색 목록을 먼저 닫고, 그다음 이전 서재 화면으로 이동합니다. 노트 탭을 바꾼 뒤에도 서재로 돌아올 수 있고 서재 첫 화면에서는 앱 안에 머무릅니다. 필기에서 홈으로 돌아갈 때 이전 화면을 슬라이드하며, 시스템의 모션 줄이기 설정을 따릅니다. OS의 강제 종료·앱 전환은 제어하지 않습니다.
- 더 선명한 블루 포인트, 활성 도구와 탐색 버튼, 읽기 쉬운 글자 대비를 적용했습니다. 저장된 종이·필기 색은 그대로 유지합니다.
- 설정의 **업데이트 확인**은 항상 표시됩니다. 새 Service Worker를 다운로드한 후 **저장 후 새 버전 적용**을 누르면 필기를 먼저 저장하고 업데이트합니다. 최신·오프라인·다운로드 실패 상태를 표시하며 사이트 데이터는 삭제하지 않습니다.
- 필기 화면에서는 아래로 당겨 새로고침하는 동작과 F5·Ctrl/Cmd+R을 막습니다. 브라우저 자체의 새로고침·닫기에는 지원되는 환경에서 확인창을 표시합니다. 앱의 명시적인 업데이트는 저장 후 새로고침을 허용합니다. 모바일 OS 강제 종료나 브라우저 UI를 웹에서 완전히 차단할 수는 없습니다.

## 검증

`npm test`는 빠르게 교차하는 지우개, 부분 지우개 필압 유지, 올가미, 대형 획 경계, 저장 스냅샷 순서, 실패 트랜잭션 롤백·재시도, 첫 페이지 미리보기 갱신을 검사합니다.

`npm run test:e2e`는 production build를 실제 Chromium 계열 브라우저에서 실행합니다. 노트 생성, DevTools 프로토콜의 **펜 입력·압력**, 필기 저장, 실행 취소·다시 실행, 새로고침 복원, 텍스트·페이지 추가, 휴지통 복구, 모바일 폴더 관리, 오프라인 재실행, **오프라인에서 PDF 가져오기·주석·내보내기·전체 백업·복원**을 검증합니다.

추가 회귀 검사에는 최신 Map API를 제거한 창·PDF 워커에서의 PDF 열기, 손상된 PDF 표시 실패 후 홈 복귀와 필기 보존, 실제 Service Worker 버전 교체 후 노트 보존, 첫 S펜·터치 탭의 도구 전환, 핀치/휠 제스처 도중 Canvas 버퍼 재생성 0회, 새로고침 단축키 차단 및 브라우저 확인창이 포함됩니다. 벡터 내보내기 검사는 출력 PDF에 불필요한 전체 페이지 비트맵이 없고 회전된 원본도 벡터 Form으로 남는지 검사합니다.

탐색 검사는 설정·폴더·즐겨찾기·최근·휴지통·모바일 탐색 목록·메뉴에서 실제 History 뒤로가기를 실행하고, 홈에서 반복해도 같은 문서에 머무르는지 확인합니다. 필기 후 슬라이드 복귀와 저장 보존, 탭 전환 후 뒤로가기, 서로 다른 PDF 페이지 미리보기 생성과 재실행 후 캐시도 검사합니다.

실제 갤럭시 탭 하드웨어 테스트는 별도로 필요합니다. PC 자동화가 S펜의 실제 지연이나 손바닥 크기 입력을 재현하지는 못합니다.

## 현재 제한과 다음 단계

요청한 Phase 1을 기반으로 Phase 2–4의 주요 도구를 연결한 첫 버전입니다. 전체 요구사항이 모두 완료된 최종 네이티브 노트 앱 수준으로 간주하면 안 됩니다.

- **완전한 연속 다중 페이지 스크롤은 미구현**입니다. 현재는 한 페이지를 스크롤하며 버튼·썸네일·페이지 번호로 전환하고, 마우스 휠로 아래 경계에서 다음 페이지로 이어갈 수 있습니다.
- 실행 취소 이력은 현재 페이지의 오브젝트 편집 40단계이며, 페이지 전환 후 초기화됩니다. 페이지 삭제·속지 변경은 이 이력으로 되돌릴 수 없습니다. 노트 삭제는 휴지통에서 복구됩니다.
- 예측 입력(`getPredictedEvents`)은 미사용입니다. 실제 S펜 튜닝과 긴 필기 성능 측정이 다음 단계입니다.
- 웹 팜 리젝션은 하드웨어·OS·브라우저 영향을 받습니다. 네이티브 수준을 보장하지 않습니다. S펜 에어 액션과 측면 버튼의 브라우저 미노출 동작은 제어하지 못합니다.
- 텍스트·이미지는 삽입 후 올가미로 이동·복사·확대·삭제할 수 있습니다. 기존 텍스트 내용 직접 수정, 이미지 자르기·회전, 선택 핸들 직접 드래그 크기 조절은 미구현입니다. 크기는 선택 툴바 +/−로 조절합니다.
- 노트 내 검색은 **입력 텍스트**만 지원합니다. 손글씨 OCR, PDF 본문 검색, 모든 검색 결과 목록은 미구현입니다.
- 펜·형광펜·도형은 PDF에서도 벡터로 유지됩니다. 직접 입력한 한글 등 유니코드 텍스트는 브라우저 글꼴 모양을 보존하기 위해 글상자만 4배 해상도 이미지로 포함합니다. 원본 이미지·스캔 PDF 자체의 해상도를 높이지는 못합니다. MyNotes에서 획별 재편집하려면 원본 백업도 보관하세요.
- 암호화·권한 제한 PDF, 양식 편집, PDF 자체 링크·주석 상호작용은 지원 범위 밖입니다. PDF 150MB, 이미지 20MB/4천만 화소, 백업 복원 400MB 제한이 있습니다. 대형 파일은 기기 RAM의 제약을 받습니다.
- 기기 간 클라우드 동기화·로그인·협업·자동 클라우드 백업은 없습니다. 동일 브라우저 프로필 내 저장만 지원합니다. 다중 창에서 동일 노트를 동시에 편집하는 협업 충돌 해결은 미구현입니다.
- 자동 저장은 완료된 획/편집 직후 시작합니다. 브라우저 강제 종료가 저장 완료 전에 발생하면 마지막 진행 중 획은 유실될 수 있습니다. 영구 저장은 브라우저의 허가에 따릅니다.
- 재실행 시 서재를 엽니다. 저장한 페이지와 필기는 보존되지만 마지막 탭·선택 도구·확대율 복원은 미구현입니다.

## GitHub Pages 배포

`.github/workflows/deploy.yml`은 `main` push마다 단위 테스트 → 빌드 → Chromium 브라우저 테스트 → Pages 배포를 실행합니다. PR에서는 테스트만 실행합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 설정합니다.
2. `main`에 push하거나 Actions → **Test and deploy MyNotes PWA → Run workflow**를 실행합니다.
3. Actions의 `deploy` 성공 후 https://znh0o.github.io/mynotes/ 에서 확인합니다.

```sh
git remote add origin https://github.com/znh0o/mynotes.git
git push -u origin main
```

`base`, manifest `start_url`·`scope`, Service Worker fallback은 모두 `/mynotes/`입니다. 저장소 이름을 바꾸면 `vite.config.ts`와 테스트의 경로도 함께 바꾸세요. GitHub Pages에는 서버나 별도 환경변수가 필요 없습니다.

## 갤럭시 탭 실기기 확인 절차

1. PWA 설치 후 가로·세로·분할 화면에서 서재와 툴바를 확인합니다.
2. S펜으로 느린 곡선·빠른 글씨·점·가벼운/강한 압력 획을 작성합니다.
3. 펜이 닿는 동안 손바닥을 올려 추가 획이 생기는지 확인합니다. 손가락 필기를 꺼서 시작합니다.
4. 두 손가락으로 50%/200% 확대 후 같은 PDF의 글자 위치에 선을 긋고 정합성을 확인합니다.
5. 앱을 닫았다 다시 열어 필기를 확인하고, 비행기 모드에서 앱을 재시작합니다.
6. 비행기 모드에서 저장한 PDF를 가져오고 필기 후 내보낸 파일을 PDF 뷰어에서 비교합니다.
7. 백업을 다운로드하고 복원하여 기존 노트와 “(복원)” 사본이 모두 남는지 확인합니다.
8. 브라우저 개발자 도구의 저장소 제한 또는 테스트 환경에서 저장 실패를 유발하고 실패 안내·재시도를 확인합니다. 실제 중요한 데이터를 지우며 테스트하지 마세요.
